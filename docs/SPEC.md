# 活動報到系統 規格書

活動：2026 台灣普利司通經銷商年度大會（2026 BRIDGESTONE DEALER CONVENTION）
版本日期：2026-11-20

## 1. 專案概述

參加者掃描現場 QR Code，用自己的手機完成報到，報到後在同一個頁面取得房號、晚宴桌次、問卷與兌換 QR Code；工作人員用後台即時掌握到場狀況。

| 角色 | 使用裝置 | 主要操作 |
| --- | --- | --- |
| 參加者 | 自己的手機 | 掃碼報到、看房號桌次、填問卷、出示兌換 QR Code |
| 櫃檯工作人員 | 筆電或手機 | 協助報到、掃描或人工兌換贈品與餐盒 |
| 主辦方 | 筆電或手機（不投影） | 看報到人數、未到名單、兌換統計 |

活動含住宿；問卷開放時間為 12/6 21:00 至 12/7 08:30。全站 RWD。

## 2. 測試站與正式站

所有內容先上測試站，客戶確認後再發佈到正式站；之後每次更新都走同一個流程。

| 環境 | 用途 | 資料 |
| --- | --- | --- |
| 測試站 | 功能與文字確認、供客戶試操作 | 假資料，可隨時清空重來 |
| 正式站 | 活動現場使用 | 正式名單，與測試站資料完全分開 |

活動當天鎖定正式站，不發佈新版，除非是緊急修正。

## 3. 技術架構（Cloudflare）

| 項目 | 測試站 | 正式站 |
| --- | --- | --- |
| 網址 | test-checkin.<網域> | checkin.<網域> |
| 程式 | Cloudflare Worker（前端頁面 + API） | 同一份程式，確認後發佈 |
| 資料庫 | D1 `checkin-test` | D1 `checkin-prod` |
| 後台登入 | 獨立密碼 | 獨立密碼 |

- 每店一份問卷、每店一份贈品、每人一份餐盒，都由 D1 的唯一限制或條件式更新保證，多人同時送出也不會重複。
- 時間以伺服器時間（台灣時間）判斷。
- 現場監控每 5 秒自動更新。

## 4. 報到流程

```
掃描 QR Code
  → 輸入姓名（精確搜尋）
      ├ 查無資料 → 顯示「查無資料，請洽報到櫃檯」
      ├ 僅一筆   → 確認身分
      └ 同名多筆 → 列出店名讓本人選擇 → 確認身分
  → 閱讀住宿安全及注意事項，勾選同意（未勾選無法送出）
  → 確認報到
  → 報到完成頁
```

- 已報到者再次查詢，直接回到報到完成頁，不重複報到。
- 報到開放時間：先設為立即開放，後台可設定開始與結束時間；未開放時顯示開放時間。
- 沒有手機或查無資料的人，由櫃檯工作人員在後台代為報到。
- 同店同名同姓不會發生，姓名 + 店名即可唯一識別。

## 5. 報到完成頁

報到完成頁是參加者整個活動期間的個人頁，重新掃碼並輸入姓名（或用已存的 token 連結）即可再次打開。

| 區塊 | 內容 | 何時可用 |
| --- | --- | --- |
| 報到成功 | 姓名、店名、報到時間 | 報到後立即 |
| 入住房號 | 房號 | 報到後立即 |
| 晚宴桌次 | 桌次 | 報到後立即 |
| 注意事項 | 所有人相同的簡單注意事項（後台可編輯） | 報到後立即 |
| 餐盒兌換 QR Code | 個人專屬 QR Code + 兌換狀態 | 報到後立即，會議中間使用 |
| 滿意度問卷 | 問卷入口按鈕 | 12/6 21:00 至 12/7 08:30；其他時間顯示「尚未開放（開放時間）」或「已截止」 |
| 贈品兌換 QR Code | 店家專屬 QR Code + 兌換狀態 | 該店家填完問卷後才出現 |

已兌換的項目顯示「已兌換」與兌換時間。

## 6. 滿意度問卷與贈品

問卷與贈品以「店家」為單位：每家店只收一份問卷、只能領一次贈品。

**問卷**
- 只在開放時間內可填寫（預設 12/6 21:00 – 12/7 08:30，後台可調整），以伺服器時間為準。
- 題目待訂：先放 3 題示範題，後台可編輯題目與題型（單選、評分 1–5、簡答）。

**同店家兩人同時填寫**
1. 進入問卷時取得店家填寫鎖（10 分鐘）。同店其他人看到「同店 OOO 正在填寫，請稍候」。鎖逾時自動釋放。
2. 問卷資料表對店家設唯一限制，第一份送出成功，後送出者被資料庫拒絕。
3. 本店已完成時，直接顯示「本店已由 OOO 於 HH:MM 填寫完成」與贈品 QR Code。

**贈品**
- 填完問卷立即產生該店家的贈品 QR Code，同店任一人的完成頁都看得到。
- 工作人員掃碼或用人工兌換後標為已兌換，再掃會顯示「已於 HH:MM 兌換」。
- 限量：預設 50 份，後台可設定。每次兌換扣 1，送完後顯示「贈品已兌換完畢」，問卷仍可填寫。

## 7. 餐盒兌換

- 每人一份、只有一個領取時段；未報到者不能領。
- 參加者出示完成頁的餐盒 QR Code，工作人員用後台掃碼核銷。
- 人工兌換鈕：手機太暗、貼防窺片或掃不到時，參加者在自己的畫面按「人工兌換」，由工作人員輸入 4 位數兌換碼確認。
- 工作人員也可在後台搜尋姓名直接按兌換。
- 兌換後顯示「餐盒已領取 HH:MM」，重複掃碼提示已領。
- 贈品兌換也使用同一套「QR Code + 人工兌換鈕」機制。

## 8. 住宿安全及注意事項

確認身分後、報到完成前顯示，必須勾選同意才能報到；系統記錄同意時間。文字見 `docs/hotel-rules.md`（後台可修改）。

## 9. 現場監控後台

需登入密碼。多台裝置同時開啟會自動同步（每 5 秒更新）。

| 功能 | 內容 |
| --- | --- |
| 報到人數 | 已報到 / 應到人數、報到率 |
| 未到名單 | 姓名、店名、房號、桌次，可依店名或桌次篩選 |
| 已報到名單 | 含報到時間，可搜尋 |
| 櫃檯代報到 | 工作人員搜尋姓名後代為報到 |
| 問卷統計 | 已填店家數 / 總店家數 |
| 贈品統計 | 已兌換數、剩餘庫存 |
| 餐盒統計 | 已領 / 應領人數 |
| 掃碼核銷 | 開啟相機掃贈品與餐盒 QR Code |
| 名單匯入匯出 | 活動前匯入 CSV；活動後匯出報到、問卷、兌換紀錄 |
| 設定 | 報到開放時間、問卷開放時間、贈品數量、注意事項文字、住宿規範文字、問卷題目、人工兌換碼 |

## 10. 資料欄位

主辦方只需提供 CSV：`姓名,店名,房號,桌次,備註`（備註選填）。其餘欄位由系統產生。資料表設計見 `docs/schema.sql`。

**參加者**：姓名、店名、房號、桌次、備註、報到時間（空白 = 未到）、住宿規範同意時間、報到方式（自助 / 櫃檯）、餐盒兌換時間、個人 token
**店家**（依名單店名自動建立）：店名（唯一）、問卷填寫人 / 時間、贈品兌換時間、贈品 token
**問卷**：店家（唯一）、填寫人、答案（JSON）、送出時間

## 11. 客戶已確認事項

| 項目 | 決定 |
| --- | --- |
| 報到方式 | 參加者掃 QR Code 自行報到 |
| 報到欄位 | 姓名；同名時以店名確認 |
| 報到開放時間 | 先設為立即開放，後台預留開始與結束時間設定 |
| 名單、房號、桌次 | 先用假資料，之後以 CSV 匯入 |
| 同店同名同姓 | 不會發生 |
| 簡單注意事項 | 所有人相同，後台可編輯 |
| 滿意度問卷題目 | 待訂 |
| 贈品數量 | 預設 50 份，後台可設定 |
| 餐盒 | 每人一份、一個領取時段，需先完成報到 |
| 同店問卷填寫鎖定 | 需要，每店只能填一次 |
| 現場裝置 | 工作人員用筆電與手機，不投影 |
| 版面 | 全站 RWD |
